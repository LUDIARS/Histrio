# ロールモデルエンジン — 人生脚本 × 状況対応

## 0. ねらい (2026-08-12 neco 指示)

persona の「人格らしさ」を seed 乱数の癖ではなく、**説明可能な 2 層のカテゴライズ**で持つ。

1. **脚本層 (静的・長期)** — 交流分析 (TA) の人生脚本を参考に、persona の一貫した傾向を
   構造化プロファイルで持つ。
2. **状況層 (動的・発話時)** — 会話の場の状態を分類し、脚本プロファイルと掛け合わせて
   その場の**ロールモデル (振る舞いの型)** を決定論的に選ぶ。

LLM は使わない (persona エンジンは heuristic の原則を維持)。曖昧な状況分類だけ、描画に
使う中央 Haiku 呼び出しへ相乗りさせる (§3)。

## 1. 脚本層 — persona プロファイル

persona ごとに次の構造化ベクトルを正本として持つ (`personas` テーブルへ列追加ではなく
`persona_profiles` を新設):

| 軸 | 語彙 | 表現 |
|---|---|---|
| エゴグラム | CP / NP / A / FC / AC | 各 0-100 の 5 次元ベクトル |
| ドライバー | 完全であれ / 喜ばせろ / 努力せよ / 強くあれ / 急げ | 主 1 + 副 1 |
| 基本的構え | 自他肯定 / 自己肯定・他者否定 / 自己否定・他者肯定 / 自他否定 | 1 値 (既定: 自他肯定) |
| 脚本傾向 | 勝者 / 非勝者 / 敗者 — の穏当版として 前進型 / 維持型 / 慎重型 | 1 値 |

- 初期値は既存の seed + signals から決定的に導出する (同じ seed → 同じプロファイル。
  既存 persona の見た目の連続性を保つ)。
- AI persona に「敗者脚本」を字義どおり持たせるのは有害無益なので、脚本傾向は
  行動傾向 (前進/維持/慎重) へ翻訳して保持する。エゴグラム・ドライバーも
  「診断」ではなく発話スタイルの設計語彙として使う。

## 2. 状況層 — 場の分類とロールモデル選択

### 2.1 状況カテゴリ (決定的シグナルで分類)

| カテゴリ | 主なシグナル |
|---|---|
| 発散 (アイデア出し) | 質問文比率高・話者多数・短文連鎖 |
| 収束 (決定前) | 選択肢列挙・ask カード近傍・「どれ」語彙 |
| 停滞 | 発言間隔増大・同一話者連投・未回答質問滞留 |
| 対立 | 否定語比率・引用応酬 |
| 祝福/完了 | マージ通知・完了報告・絵文字密度 |
| 雑談 | 上記いずれでもない低密度会話 |

シグナルは buffer 内の決定的統計のみで算出する (話者数・発言間隔・文長・語彙マッチ・
直近イベント種別)。

### 2.2 ロールモデルカタログ

| ロール | 振る舞いの型 | 相性の良いプロファイル例 |
|---|---|---|
| ファシリテーター | 論点整理・発言を促す | NP/A 高・喜ばせろ |
| 批評者 | 前提を突く・リスク指摘 | CP/A 高・完全であれ |
| 推進者 | 決定を後押し・次の一手提示 | FC 高・急げ・前進型 |
| 応援者 | 承認・励まし | NP 高・自他肯定 |
| 分析者 | データ・事実の補足 | A 高・強くあれ |
| 道化 | 場を緩める・ぼやき | FC 高・雑談/停滞時 |
| 静観 | 発話しない (参加見送り) | AC 高・慎重型・対立時 |

### 2.3 選択関数 (決定的)

```
score(role) = Σ 状況×ロール基礎重み (matrix)
            + プロファイル適合度 (エゴグラム内積 + ドライバー/構えボーナス)
            + 学習補正 (persona×role×状況の feedback 重み)
最高 score のロールを採用。「静観」が勝ったら発話しない。
```

- matrix と重みは設定データ (seed 同梱・PUT で注入可、rules の決定的レビューを通す)。
- 同点は persona id + 状況の hash で決定的にタイブレークする (乱数不使用)。
- 採用ロールは描画 (render) の intent/tone と 会話ポリシー (返信確率補正) に渡す。

## 3. 曖昧時の補助分類 (追加コストなし)

決定的分類の確信度が閾値未満のときだけ、どのみち発話描画で呼ぶ中央 Haiku の
プロンプトに状況分類の選択を相乗りさせる (呼び出し回数は増やさない)。Haiku の分類は
その場限りで使い、プロファイル・学習重みへは直接書き込まない。

## 4. 学習 (heuristic)

- `persona_feedback_log` (ぼやき・session-end 学習・人間のリアクション) を
  persona×role×状況の重みへ決定的に畳み込む (人間の 👍/返信 = 正、無反応の連続 = 弱負)。
- プロファイル自体の変動は緩慢 (エゴグラムの 1 日あたり変動上限を設ける)。急変は
  「人格が壊れた」体験になるため禁止。
- 重み・プロファイルの変更履歴は監査可能に保存し、WebUI から現在値と根拠を見られるようにする。

## 5. Discutere への応用

- 討論生成では状況カテゴリを Di 側が明示指定する (発散→収束→対立→合意の脚本を Di が組む)。
- ロールカタログに討論用ロール (論者 A/B・司会・書記) を namespace `di` で追加できる。
- 同じ選択関数・同じプロファイル語彙を使うことで、Cc の会話と Di の討論で persona の
  一貫性が保たれる。

## 6. 受け入れ基準

- [ ] persona プロファイル (エゴグラム/ドライバー/構え/傾向) が seed から決定的に導出され、
      既存 persona で再現可能である。
- [ ] 状況分類は buffer 統計のみで動き、LLM 追加呼び出しをしない (相乗りのみ)。
- [ ] 同一入力に対するロール選択が常に同一である (乱数・時刻依存なし)。
- [ ] 「静観」ロールが選ばれた場合は発話しない。
- [ ] feedback による重み更新が上限付きで、変更履歴を監査できる。
