# 仮想人格 — 人生脚本パターン × OK牧場

## 0. ねらい (2026-11-19 neco 指示)

AI の「仮想人格」を定義する。人格は**人生脚本のパターン**に合わせて持ち、内部の会話ロジックで
反応を決める**主要因を脚本パターン**にする。議論内容に対する**立場ベクトル**を脚本パターンから
持った後、**OK牧場 (I'm OK, You're OK)** を認識して会話する。このパターンは Histrio に記録され、
運用の中で作りこまれる。

[role-model-engine.md](role-model-engine.md) の脚本層は、エゴグラム / ドライバー / 基本的構え /
脚本傾向を並列に加算してロール選択に使っていた。本書ではこれを再構成し、

- **脚本パターン = 反応の主因** (議論内容 → 立場ベクトルを決める)
- **エゴグラム等 = 従属項** (表れ方: 声色・強度・ストレス時の振れを調整する)

とする。LLM 不使用・決定的・説明可能の原則は維持する。

## 1. 仮想人格の定義

`persona_profiles` ([role-model-engine.md §1](role-model-engine.md#1-脚本層--persona-プロファイル)) を拡張し、
`script_pattern_id` を**必須**列として持つ。

| 要素 | 位置づけ | 役割 |
|---|---|---|
| 脚本パターン | **主** (1 個) | 反応表 (§2.2) を持ち、立場ベクトルの主因になる |
| ドライバー | 従 (主 1 + 副 1) | ストレス時に脚本パターンの反応を強める (`driver_boost`) |
| 基本的構え | 従 | OK牧場における自分側の平常象限 (§4.1) |
| エゴグラム (CP/NP/A/FC/AC) | 従 | 表現 (声色・語調・強度) の調整のみ。立場・ロール選択には加算しない |
| 脚本傾向 (前進 / 維持 / 慎重) | 従 | 立場ベクトル base の微調整と描画トーン |

- 全要素は既存の seed + signals から決定的に導出する (同じ seed → 同じ人格)。
- 既存 persona は seed から脚本パターンを 1 個決定的に割り当てて移行する (hash(seed) でカタログ順に割当て)。
- 脚本・構えは AI の設計語彙であり、**人間参加者に脚本・構えをラベル付けして表示・記録しない**。

## 2. 脚本パターン

### 2.1 カタログ (初期 6 種)

TA の process script (時間構造化された脚本パターン) を、会話での反応傾向へ翻訳して持つ。

| id | パターン | 会話反応 (健全側を基準に描画) |
|---|---|---|
| `until` | 〜するまでは | 条件が揃うまで保留し、前提確認を先に求める |
| `after` | 〜した後で | 良い流れの後の揺り戻しを警戒し、成功・決定直後にリスクを挙げる |
| `never` | 決して | 新案に対して現状維持へ寄る |
| `always` | いつも | 既知の解法・前例に寄せる |
| `almost` | もう少しで (Over and Over) | 完了間際に追加検討を差し込む |
| `open_ended` | 結末のない | 完了後に「次に何をするか」を問う |

- カタログは**設定データ** (seed 同梱)。`PUT /v1/script-patterns` で注入し、rules と同じ決定的レビューを通す。
  namespace は `cc` / `di` / `shared`。
- 各パターンは**健全側**と**ストレス側**の 2 面を持つ。既定は健全側で描画し、ドライバーのストレス発火 (§4.1)
  時のみストレス側の表現へ寄せる (例: `until` 健全側 = 「前提を揃えてから進めよう」 / ストレス側 = 「まだ早い」)。
- パターンごとに base 立場ベクトル・反応表・OK牧場の揺れ先 (§4.1) をデータとして持つ。

### 2.2 反応表

```
reaction(pattern, content_features) -> stance_delta (§3 の 5 軸)
```

`content_features` は buffer の決定的統計と語彙マッチで抽出する (LLM 不使用)。

| feature | 主なシグナル |
|---|---|
| 新規提案 | 「〜してはどうか」「案」等の提案語彙、新規トピック開始 |
| 決定・合意 | ask 回答、「決定」「それで」等の合意語彙 |
| リスク・失敗 | エラー通知、「失敗」「懸念」等の語彙 |
| 完了・成功 | マージ通知、完了報告 |
| 前例参照 | 「前回」「以前」「いつもの」等の参照語彙、過去スレッド引用 |
| 未確定・条件 | 「もし」「〜なら」「未定」等の条件語彙、未回答質問 |

反応表の例 (係数は設定データ。符号の方向のみ示す):

| pattern \ feature | 新規提案 | 決定・合意 | リスク・失敗 | 完了・成功 | 前例参照 | 未確定・条件 |
|---|---|---|---|---|---|---|
| `until` | act − | act − / certainty − | act − | ± | certainty + | act −− |
| `after` | ± | certainty − | engage + | certainty − / engage + | ± | ± |
| `never` | support −− | support − | support + | ± | support + | act − |
| `always` | support − | ± | ± | certainty + | support ++ / certainty + | ± |
| `almost` | engage + | act − | engage + | act − / certainty − | ± | engage + |
| `open_ended` | engage + | ± | ± | engage ++ / act + | ± | engage + |

## 3. 立場ベクトル

話題 (thread / topic) 単位で、議論内容への立場を 5 軸 (各 -1..+1) で持つ。

| 軸 | -1 | +1 |
|---|---|---|
| `support` | 反対 | 賛成 |
| `act` | 保留 | 今すぐ |
| `engage` | 距離を置く | 積極参加 |
| `certainty` | 疑う | 確信 |
| `focus` | 自分の懸念 | 相手・場の利益 |

```
stance = clamp(
    base(pattern)
  + Σ_f reaction(pattern, f) * w_pattern
  + driver_boost(driver, stress)
)
```

- `w_pattern` が最大重み。エゴグラムは**加算しない** (表現調整のみ)。
- 同一入力 → 同一ベクトル。乱数・時刻依存なし。
- 新しい発言が来たら、その発言の features 分だけ差分更新する (話題全体の再計算と結果が一致すること)。

## 4. OK牧場の認識

### 4.1 自分の象限

象限: `I+U+` (自他肯定) / `I+U-` (自己肯定・他者否定) / `I-U+` (自己否定・他者肯定) / `I-U-` (自他否定)。

- 平常位置は基本的構え (§1、既定 `I+U+`)。
- ドライバーのストレス発火 + 場との食い違い (立場ベクトルと場の多数の向きの乖離) が閾値を超えると、
  パターン別の揺れ先へ一時移動する (例: `until` → `I-U+`、`always` → `I+U-`)。揺れ先はパターンデータに持つ。
- 移動後は発話ごとに `I+U+` へ減衰して戻る。

### 4.2 相手の象限推定

- 発言の 否定語 / 自己卑下語 / 相手否定語 / 承認語 / 謝罪語 / 命令形 の比率から決定的に推定する。
- 確信度不足のときのみ、[role-model-engine.md §3](role-model-engine.md#3-曖昧時の補助分類-追加コストなし) と同じく
  描画で呼ぶ中央 Haiku へ相乗りさせる (追加呼び出しなし)。
- 推定結果はその場の会話操作にのみ使い、**人間の属性として保存しない**。

### 4.3 会話操作 (Ernst の OK Corral を会話向けに翻訳)

| 自分の象限 | 操作 | 会話での振る舞い |
|---|---|---|
| `I+U+` | get-on-with (共に進む) | 率直に述べ、相手案と統合する |
| `I+U-` | get-rid-of → **建設的反論へ置換** | 根拠付きの異論を述べる。相手を否定しない |
| `I-U+` | get-away-from (回避) | 一歩引く・質問で返す・相手案に乗る |
| `I-U-` | get-nowhere-with | 静観 (発話見送り) か、論点の棚上げを提案する |

- 相手の推定象限が `I+U+` 以外のときは、自分を `I+U+` へ寄せる補正をかける (場を自他肯定へ戻す)。
- **安全規則**: 人間を否定・攻撃・ラベリングする発話は描画しない (get-rid-of は常に建設的反論で出す)。

### 4.4 ロール選択への接続

```
content_features → stance → corral(self, other) → operation

score(role) = 状況 × ロール基礎重み (matrix)
            + operation × ロール適合        ← 主
            + stance × ロール適合
            + 学習補正 (persona × pattern × role × 状況)
最高 score のロールを採用。
```

- [role-model-engine.md §2.3](role-model-engine.md#23-選択関数-決定的) の選択関数を本式で置き換える。
  エゴグラム内積はロール選択から外し、tone 調整へ移す。
- 同点タイブレークは persona id + 状況の hash (乱数不使用)。
- 採用ロール・立場ベクトル・操作を render の intent / tone へ渡す。
- 「静観」または get-nowhere-with の静観が選ばれたら発話しない。

## 5. Discutere への応用

- 論者ごとに脚本パターンを指定する。論者間の立場ベクトルの差がそのまま討論の対立軸になる。
- 司会ロールは場を `I+U+` へ戻す介入 (要約・相互承認・論点の棚上げ) を担う。

## 6. 記録と作りこみ

| 表 | 内容 |
|---|---|
| `script_patterns` | カタログ・反応表・揺れ先・健全 / ストレス面。版管理 (version id) |
| `persona_profiles` | `script_pattern_id` (+ 版) を含む人格定義 |
| `persona_decision_log` | 発話ごとの features・立場ベクトル・自他象限・操作・採用ロール・根拠 |
| `persona_feedback_log` (既存) | 判断ログ id で紐付ける |

- 判断ログ × 結果 (feedback) を、重みと反応表係数へ決定的に畳み込む。1 日あたりの変動上限を設ける (急変禁止)。
- パターンの追加・改訂は `PUT /v1/script-patterns` で版を上げ、決定的レビューを通す。旧版の判断ログは版 id で再現できる。
- WebUI / API で「パターン → 立場ベクトル → 象限 → 操作 → ロール」の根拠を辿れる。

## 7. 受け入れ基準

C++23 の API・判断処理を、一時 SQLite データベースと描画クライアントのテストダブルを使って ctest で検証する。

- [ ] 全人格が脚本パターンを 1 個、seed から決定的に持つ (既存 persona も移行で再現可能)。
- [ ] 立場ベクトルは反応表が主因で、同一入力に同一ベクトル。エゴグラムを変えてもベクトルは変わらない。
- [ ] 象限推定と操作選択が決定的で、LLM の追加呼び出しをしない (相乗りのみ)。
- [ ] get-rid-of は常に建設的反論として描画され、人間を否定・ラベリングする発話が出ない。
- [ ] 相手の象限推定を人間の属性として保存しない。
- [ ] 判断ログから発話の根拠 (パターン → ベクトル → 象限 → 操作 → ロール) を再現できる。
- [ ] 学習による変動が上限付きで、パターンの版と変更履歴を監査できる。
