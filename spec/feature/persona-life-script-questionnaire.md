# 仮想人格のアンケート

## 0. ねらい (2026-11-24 neco 指示)

- 「アンケートベースで人生脚本を特定する仕組み」は **人が答える側と、人格が答える側の両方** に使う (neco「両方が正しいかも」)。
- 人が答える側は Discutere のつくり手インサイトで実装済み (DI-CI-08 / DI-CI-09、Discutere #4133)。
- 本書は人格が答える側。今は脚本パターンを seed の hash から割り当てている
  ([virtual-persona-life-script.md §1](virtual-persona-life-script.md#1-仮想人格の定義))。
  人格の設定 (説明文・口調・経歴) と脚本パターンが無関係に決まるため、設定に沿わない反応が出る。
  人格自身にアンケートへ答えさせ、その採点で脚本パターンを決める。

## 1. 境界

| する | しない |
|---|---|
| 仮想人格 (namespace `cc` / `di` / `shared` の AI 人格) がアンケートに答える | 人の回答・採点結果・追加質問の答えを受け取る・保存する (Discutere の DI-CI-04 と同じ線) |
| 回答を一度だけ LLM で作り、版と一緒に保存する | 毎回の会話で答え直す (人格が揺れる) |
| 採点はロジック (Discutere の `score-life-script` と同じ手順) | 採点に LLM を使う |
| 人格への追加質問の答えを「反応の具体例」として描画に渡す | 追加質問の答えで得点・脚本パターンを書き換える |
| 代理議論の人物パック (実在の公開レビュー由来) は対象外 | 実在の人の代わりに AI が答える (「他人が本人について答える形では使わない」に反する) |

## 2. 流れ

1. **対象**: 説明文 (人格の設定) を持つ仮想人格。説明文が無い人格は従来どおり seed から割り当てる。
2. **回答**: アンケートの 4 セクションごとに 1 回ずつ LLM を呼ぶ (計 4 回)。
   - 渡すもの: 人格の説明文、セクションの指示、設問文と選択肢 (並べ替え済み、尺度名・逆転の有無は渡さない)。
   - 返すもの: `{ 項目ID: 1..4 }` / `{ FC-n: "a".."e" }` の JSON。形・範囲・ID を検査し、外れたら保存しない (無言で埋めない)。
   - 1 問ずつにしない理由: 人の場合は前の答えの影響を避けるために 1 問ずつ出すが、LLM は呼び出しごとに履歴を持たないので
     セクション単位でも影響は同じ。呼び出し回数を 51 → 4 に減らす。
3. **採点**: Discutere の採点手順を C++ に移したもの。Discutere の回答例 → 特徴カード例と同じ結果になることを受入テストにする。
4. **割り当て**:
   - 脚本パターン = プロセス脚本の優位の 1 位。優位が無ければ seed からの割り当てに戻し、`source=seed` と記録する。
   - ドライバー (主 1 + 副 1) = ドライバーの優位。基本的構え = 自己・他者の帯 (境界は「境界」のまま)。
   - 確度 (高 / 中 / 低) を一緒に保存する。
5. **追加質問 (任意)**: Discutere の `plan-life-script-followups` と同じ選び方で話題を決め、人格に設定どおり答えさせる。
   答えは `persona_reaction_examples` に保存し、描画 (`/v1/render`) で「この人ならこう言う」の例として渡す。
6. **保存**: `persona_questionnaire_runs` に 回答・採点結果・アンケートの版・LLM の役割名・指示文の版・実行日時 を残す。
   `persona_profiles` には `script_pattern_id` / ドライバー / 構え / 確度 / `source` (questionnaire | seed) と run の id を入れる。

## 3. 決定性

- LLM を使うのは回答と追加質問の答えを**作るときの 1 回だけ**。作った回答は保存し、以後は保存した回答から決定的に人格を導く。
- 同じ回答 → 同じ脚本パターン・ドライバー・構え (既存の受入基準「同じ seed → 同じ人格」を「同じ回答 → 同じ人格」に広げる)。
- 答え直しは明示の操作 (`POST /v1/personas/:id/questionnaire` に `rerun: true`) だけ。前の run は残し、判断ログから旧版を再現できる。

## 4. アンケートの正本

- 設問・採点キー・追加質問の文例の正本は当面 Discutere (`skills/creator-insight/data/`)。
- Histrio は同じファイルを `data/life-script/` に**版を固定して**持つ。起動時に設問 ID `life-script-ja`、設問版 `2026-11-13`、追加質問集の参照先および独立した追加質問版 `2026-11-24` を照合する。
- 採点の受入テストは両方のリポで同じ回答例を使う。どちらかで採点キーを変えたら、もう一方も同じ版へ上げる。

## 5. API

| メソッド | パス | 内容 |
|---|---|---|
| POST | `/v1/personas/:id/questionnaire` | 回答を作って採点し、人格へ割り当てる (`rerun` 省略時、既に run があれば 409) |
| GET | `/v1/personas/:id/questionnaire` | 最新 run の採点結果・割り当て・確度 (回答そのものは admin のみ) |

- `?namespace=cc|di|shared` は人格を登録した名前空間を指定する。POST の本文は省略または `{"rerun":true}` を含むオブジェクト。説明文が空なら 400 を返し、従来の seed プロファイルを使う。不正なモデル応答は 502 を返し、前の run とプロファイルを保持する。
- GET で回答本体を含めるには、運用側で `HISTRIO_QUESTIONNAIRE_ADMIN_TOKEN` を設定し、対応する Bearer トークンを送る。GET と POST の結果にはキャッシュを禁止する。
- 保存済みの反応例は run ID で参照する。判断ログを使う描画も、その判断時の run を参照する。構えが境界の場合、プロフィールには境界を保存し、通常の会話操作は `get-on-with` を使う。
- `histrio-server rerun-questionnaires` は説明文を持つ仮想人格を全名前空間で処理し、成功・失敗の件数を返す。個々の保存は原子的に行う。

## 6. 受入基準

- [ ] 説明文を持つ人格がアンケートに答え、プロセス脚本の優位から脚本パターンが決まる。優位が無ければ seed に戻り `source=seed`。
- [ ] 同じ保存済み回答から、何度導いても同じ脚本パターン・ドライバー・構えになる。
- [ ] 採点が Discutere の回答例 → 特徴カード例と一致する。
- [ ] LLM の応答の形・範囲・ID が外れたら保存せず error を記録する。
- [ ] 人の回答・採点結果を受け付ける経路が無い (API・取り込み・フィードのどこにも)。
- [ ] 追加質問の答えで得点・脚本パターンが変わらない。

## 7. 決定 (2026-11-24 neco「全部推奨どおり」)

| # | 決めたこと | 決定 | 理由 |
|---|---|---|---|
| Q1 | 既存の人格 (説明文あり) を一斉に答え直させるか、新しく作る人格だけにするか | **一斉に答え直す** | seed の割り当ては設定と無関係なので、既存の人格ほど直す価値がある。費用は 1 人格 4 回の呼び出し |
| Q2 | 人格への追加質問 (§2-5) を最初から入れるか | **入れる** | 描画に「この人ならこう言う」の例が入り、設定どおりの話し方に近づく。呼び出しは最大 5 回増える |
| Q3 | アンケートの正本を共通の置き場所へ移すか | **当面は Discutere のまま、版固定のコピー** | 導入先が 2 つのうちは移設の手間が勝つ。3 つ目が出たら移す (Discutere 側の未決事項と同じ) |

実装は Q1〜Q3 の決定どおり。既存の説明文つき人格は、実装の反映後に一斉に答え直す (実行は人間の許可後)。
